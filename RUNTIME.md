границы.
  cold start (при необходимости ускорить):
  docker start maia-db maia-core-v2 maia-forwarder n8n

### "1 из 5" — исправлено (2026-10-01/02)
Нода Parse and Build SQL обрабатывала только первый item из 5,
полученных от OpenRouter за один запуск — 4 терялись молча, LLM
оплачивался за все 5. Исправлено: цикл по всем items, return
массива из 5 записей. Подтверждено живым запуском.

### Квота — перенастроена (2026-10-02)
Cron-узел "30sec" (secondsInterval=120) на практике срабатывал
каждые 60 секунд — реальный потолок 7200 вызовов/сутки против
измеренного лимита 1000/сутки. Интервал снижен до 15 минут (900с)
→ 480 вызовов/сутки (48% лимита). Узел не переименован (остался
"Cron 30sec") — решение намеренное, не трогать connections.
Подтверждено живыми запусками с равным интервалом 900с.

### Старые pending_review — решение принято, не технически реализовано
Приток новых строк (700-2900/сутки) структурно превышает бюджет
Analyzer (480/сутки). Предфильтр до LLM не строится — риск вводить
новую логику под давлением. Очередь DESC уже расставляет приоритет
(свежие вперёд) — старые записи сознательно не будут оценены в
разумные сроки (соответствует I5). Техническая мера (не
реализована, в очереди для следующего РЧ): статус
"archived_unscored" для pending_review старше N дней — явный UPDATE
по id, I2 соблюдён.
