### OpenClaw — не подключать к ядру через MCP
Решение: внешние агенты потребляют сигнал через Telegram или
read-only endpoint. К ядру не подключаются.
Почему: физическая изоляция важнее интеграции. Риск prompt
injection и широких разрешений неприемлем.
Откат: изолированный read-only endpoint при появлении реального кейса.
Дата: 2026-05-17

Решение: рутинные реакции на сигнал — через n8n workflow.
Почему: I13. Не строить то что уже работает.

контролируемый endpoint, не к ядру напрямую.

### watchdog — инцидент 27.09: порча .env остановила автоподъём
Решение: зафиксирован факт сбоя и его причина, не новая политика.
Первая строка .env содержала слитую без разделителя команду nano
с существующей переменной POSTGRES_PASSWORD (следствие правки .env
в рамках ротации ключей I7, 25.09-27.09). watchdog.sh делает
`source "$ENV_FILE"`, bash исполнял эту строку как команду, nano
падал под systemd (no TTY), set -euo pipefail обрывал весь скрипт
до docker-вызовов — ни один контейнер не поднимался автоматически.
Причина установлена: 7-шаговая верификация (journalctl, исключение
альтернативных причин, трассировка bash -x, подтверждение фиксом).
Фикс: sed-правка строки, верификация source и полного прогона в
no-TTY, финальная верификация реальным systemctl start.
Пароль частично засветился в трассировке дважды за сессию — оценено
как не компрометация, ротация не требуется (решение Архитектора).
Новое правило: после любой ручной правки .env — обязательная
проверка (`bash -n .env` или безопасный `source`) перед тем, как
считать задачу закрытой.
Дата: 2026-09-27

### Matching — DOI первичен; уточнение границ DOI-метода
Решение: matching только через DOI (title-поиск ненадёжен),
только для Announce Type = new. Расхождение title между MAIA и
OpenAlex запись НЕ блокирует (известный случай 2609.22107: MAIA
«Generalized Multimodal Foundation Model» vs OpenAlex «Fusion
Anything: A Generalized Multimodal Foundation Model»), фиксируется
в отчёте, в БД не пишется. В paper_entities пишется title OpenAlex.
Уточнение (контроль 06.10): DOI-метод
filter=doi:https://doi.org/10.48550/arxiv.{ID} подтверждён на
свежих id потока (8/8, HTTP 200, count=1, суффикс vN не нужен).
На старых id (контроль 1706.03762, 1810.04805) даёт count=0: препринт
хранится как location внутри объединённой («склеенной») записи с
чужим doi/title/year. Для старых id работает только
filter=locations.landing_page_url:http://arxiv.org/abs/{ID} (https
даёт 0); для свежих — наоборот (https 8/8, http 0/8). «Дубли» по
title, упоминавшиеся в документах, — это склеенные записи.
Для текущего потока (только new) ограничение не блокирует.
Дата: 2026-10-06/07
 
### Лимит OpenAlex — исправление: 1000 кредитов/сутки, не 100 000
Решение: прежняя цифра «100 000 запросов/сутки без ключа»
(документация, зафиксирована 21-22.09) НЕ подтвердилась замером.
Факт по заголовкам: x-ratelimit-limit 1000, 1 запрос = 1 кредит
(cost-usd 0.0001, limit-usd 0.1). Пакетный фильтр doi:a|b|c на до 25
DOI = 1 кредит (HTTP 200, URL ~1179 символов, без 414/400); порядок
результатов не совпадает с порядком запроса, привязка только по doi.
Поведение пакетов больше 25 и предел URL — не измерено.
Аномалия (диагностика Q1-Q5, 09.10): пакет из 25 DOI возвращает
посторонние работы (не arXiv, журнальные/конференционные DOI),
пакет из 5 — нет; найденные в пакете не теряются (5/5); боевой
workflow привязывает по doi и посторонних отбрасывает. Причина
посторонних НЕ измерена, расследование вне периметра. Кредит
считается на запрос, не на размер ответа.
Почему важно: тот же класс ошибки, что S2→OpenAlex — внешний
параметр взят из документации, не измерен. Урок метода усилен (см.
МЕТОДОЛОГИЯ).
Дата: 2026-10-07

### sudo — подтверждён: полный root, пароль вручную
Решение: вопрос, открытый с КОНЦЕПТ11, закрыт. У учётной записи
Архитектора полный root ((ALL:ALL) ALL). Пароль вводит Архитектор

Дата: 2026-10-13 (подтверждено шагом 0 вектора «инвентаризация
хоста», РЧ26\16)
 
### Хост — домашний ПК собственной сборки, не круглосуточный
Контекст (Архитектор): хост — рабочая машина, dual boot
Windows/Ubuntu; блэкауты; круглосуточная работа невозможна,
большую часть суток обеспечить может. Архитектор берёт на себя
увеличение времени работы хоста.
Факты инвентаризации (read-only, РЧ26\16) → RUNTIME.md.
Ключевые выводы: простои имеют минимум три причины (suspend на
экране входа GDM, переход в Windows, потеря питания/зависание,
доли не разделены); нагрузка MAIA ничтожна (<1% одного ядра,
~705 MiB RAM) — вопрос хоста про устойчивость, не мощность; риск —
сочетание старого HDD под Postgres и n8n, частых unclean shutdown,
отсутствия ИБП, data_checksums=off, бэкапов на том же HDD.
Решения по пунктам (рекомендации КОНЦЕПТ12, ОТКРЫТЫ, не
утверждены Архитектором):
  Б. GDM suspend на экране входа — устранить (mask sleep targets
     или настройка GDM), нужен sudo, решение за Архитектором.
  В. chmod/chown бэкапов (700 каталоги, 600 файлы, 2 root-файла
     через sudo) — не выполнено.
