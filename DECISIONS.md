## АРХИТЕКТУРА

### OpenClaw — не подключать к ядру через MCP
Решение: внешние агенты потребляют сигнал через Telegram или
read-only endpoint. К ядру не подключаются.
Почему: физическая изоляция важнее интеграции. Риск prompt
injection и широких разрешений неприемлем.
Откат: изолированный read-only endpoint при появлении реального кейса.
Дата: 2026-05-17

### n8n — слой реакций, не отдельный агент
Решение: рутинные реакции на сигнал — через n8n workflow.
Почему: I13. Не строить то что уже работает.
Дата: 2026-05-17

### Рой агентов — через внешние API, не через MCP внутрь ядра
Решение: внешние агенты подключаются как к источнику истины через
контролируемый endpoint, не к ядру напрямую.
Почему: безопасность, изоляция ядра.
Дата: 2026-05-17

### DDA — Documentation-Driven Architecture
Решение: документация определяет систему, не описывает её.
Сервер = источник истины. Projects = синхронизированные копии.
Git = история.
Почему: масштабирование Архитектора через документацию.
Дата: 2026-05-31
Ревью: после завершения TRANSITION.md Шага 6

### I13 — скоринг остаётся в n8n
Решение: скоринг официально признан выполняемым внутри n8n
(MAIA DeepSeek Analyzer v3.0, вызывает OpenRouter напрямую, пишет
в PostgreSQL). nc_core.py — источник промпта. /process не
используется.
Почему: миграция в nc_core.py начата, но не завершена. Система
де-факто уже работает через n8n — сначала стабилизация, миграция
отдельным вектором.
Откат: миграция в nc_core.py — отдельный вектор после стабилизации.
Дата: 2026-07-28
Ревью: после завершения плана восстановления (все шаги)

### Очередь скоринга — сортировка received_at DESC (свежие вперёд)
Решение: "PG Read pending" изменена с id ASC на received_at DESC.
Приоритет источников (CASE arxiv/hackernews → github_trending →
остальное) не тронут — работает поверх новой сортировки.
Почему: очередь обрабатывала архив с 2026-05, дошла только до
2026-08 к моменту проверки (12.09) — текущие сигналы физически не
достигались, канал уведомлений не мог сработать по актуальным
данным с самого начала проекта.
Компромисс (принят сознательно): старый backlog в приоритетной
группе arxiv/hackernews (~4507 записей, до 2026-09-01) не будет
обработан, пока сохраняется приток свежих данных — DESC всегда
выигрывает свежим на каждом тике. Архитектор выбрал этот исход
явно ("свежее важнее"), не побочный эффект.
Откат: вернуть ASC либо гибридную сортировку, если ценность
старого backlog окажется выше ожидаемой.
Дата: 2026-09-12

### Ресурсы в OpenRouter — запланировано $10, ФАКТИЧЕСКИ НЕ ОПЛАЧЕНО

проверка УЧ11\7 (02.08) подтверждала HTTP 429 на момент теста, но

Примечание: поскольку оплата так и не произведена, система
фактически продолжает работать в изначальном режиме "только
бесплатные модели" несмотря на формальную отмену этого решения.

вторым шагом позже — переносит тот же риск разрыва на другой конец
процесса, не устраняет его.

## МЕТОДОЛОГИЯ

### Проверка execution log n8n — сверка input/output обязательна
Решение: при read-only диагностике execution в n8n — не полагаться
на статус "success" в общем списке execution как признак реального
срабатывания ноды.
Почему: disabled-нода в n8n работает как pass-through (данные со
входа передаются на выход без изменений логики) и отображается со
статусом success в runData, executionTime близким к 0 — создаёт
ложное впечатление реального выполнения. Найдено на практике:
ложная тревога по "Telegram Architect"/tg-001 (14.09.2026) —
нода не отправляла сообщение, несмотря на видимость успешного
execution.
