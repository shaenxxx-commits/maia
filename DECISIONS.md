## АРХИТЕКТУРА

### OpenClaw — не подключать к ядру через MCP
Решение: внешние агенты потребляют сигнал через Telegram или
read-only endpoint. К ядру не подключаются.
Почему: физическая изоляция важнее интеграции. Риск prompt
injection и широких разрешений неприемлем.
Откат: изолированный read-only endpoint при появлении реального кейса.
Дата: 2026-05-17

### n8n — слой реакций, не отдельный агент
Решение: рутинные реакции на сигнал — через n8n workflow.
Почему: I13. Не строить то что уже работает.
Дата: 2026-05-17

### Рой агентов — через внешние API, не через MCP внутрь ядра
Решение: внешние агенты подключаются как к источнику истины через
контролируемый endpoint, не к ядру напрямую.
Почему: безопасность, изоляция ядра.
Дата: 2026-05-17

### DDA — Documentation-Driven Architecture
Решение: документация определяет систему, не описывает её.
Сервер = источник истины. Projects = синхронизированные копии.
Git = история.
Почему: масштабирование Архитектора через документацию.
Дата: 2026-05-31
Ревью: после завершения TRANSITION.md Шага 6

### I13 — скоринг остаётся в n8n
Решение: скоринг официально признан выполняемым внутри n8n
(MAIA DeepSeek Analyzer v3.0, вызывает OpenRouter напрямую, пишет
в PostgreSQL). nc_core.py — источник промпта. /process не
используется.
Почему: миграция в nc_core.py начата, но не завершена. Система
де-факто уже работает через n8n — сначала стабилизация, миграция
отдельным вектором.
Откат: миграция в nc_core.py — отдельный вектор после стабилизации.
Дата: 2026-07-28
Ревью: после завершения плана восстановления (все шаги)

## LLM

### gpt-oss-20b:free — primary
Решение: openai/gpt-oss-20b:free (primary) → nvidia/nemotron-3-super-120b
→ nvidia/nemotron-nano-9b-v2:free (fallback). gpt-oss-120b:free
исключена из цепочки целиком.
Почему: gemma/gemini недоступны (429/кредиты).

### openai/gpt-oss-120b:free — исключена из системы полностью
Решение: не используется ни как primary, ни как fallback.
Почему: непреднамеренно оказалась primary в рантайме при том, что
сама помечена "не использовать" — внутреннее противоречие.
Исправлено 2026-07-30 (docstring + default в __init__).
Откат: вернуть при пересмотре статуса модели.

Мёртвые модели: gpt-oss-120b:free, gemma-4-26b-a4b:free (429),
gemma-4-31b-it:free (429), gemini-2.5-flash (кредиты исчерпаны),
llama-3.2-3b:free (429), mistral-7b:free (404)

### Ресурсы в OpenRouter — залито $10, лимит поднят до 1000/день
Решение: разовая покупка $10. Дневной лимит бесплатных моделей
1000/день (постоянно, независимо от дальнейшего баланса).
Почему: триггер "потолок по объёму" подтверждён фактом: лимит 50
запросов/день исчерпывался за ~13 минут работы Analyzer
(10 execution, 02.08.2026, 08:11-08:24 Kyiv). Объясняет находку
AUDIT_2026-07 (score ≥ 8 не фиксировался за весь период) — контур
физически не мог работать дольше нескольких минут в сутки.
Отвергнуто: локальная LLM (усложнение архитектуры); ротация между
бесплатными моделями (лимит общий на аккаунт, не по модели).
Дата: 2026-08-02

Отменено (было в силе 2026-05-17 — 2026-08-02): работать только на
бесплатных моделях. Триггер сработал по объёму, не по качеству —
"по духу то же самое": система не могла работать без квоты вообще.

Дата: 2026-07-28 · Ревью: при переходе на Pro план

### Документация — сервер + GitHub + Projects, синхронно
Решение: сервер (~/maia_project/docs/) — источник истины. GitHub-
репозиторий и claude.ai Projects — синхронные зеркала: любая
правка вносится на сервер И в GitHub И в Projects в рамках одного
цикла, без разрыва между источниками.
Почему: последовательный порядок (Projects→сервер, затем позже
GitHub) дважды создавал расхождение на практике (см. posoh-docs:
VISION.md подменён контентом Sub-0, ROADMAP.md не содержал отметку
о завершённом Шаге 4) — проблему создавал именно разрыв во времени
между зеркалами, не сама вторичность источника.
Отвергнуто: правки сразу на сервере, синхронизация GitHub/Projects
вторым шагом позже — переносит тот же риск разрыва на другой конец
процесса, не устраняет его.
Откат: н/д — процедурное правило.
Дата: 2026-08-11 (пересмотр порядка, заменяет решение от 2026-08-02
"Projects → сервер" — с учётом опыта posoh-docs)

Известный исторический прецедент отсутствия версионирования:
