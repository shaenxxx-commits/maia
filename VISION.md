## ОБРАЗ СИСТЕМЫ

MAIA — паук в центре паутины.
Каждая нить — источник данных.
Центр собирает, квалифицирует, запоминает.
Паутина ткётся нить за нитью. Не спеша. Без пропусков.
Ядро умнеет с каждой нитью.
Архитектор — часть системы. Тоже масштабируется.

---

## ЭВОЛЮЦИЯ ПРОЕКТА

Проект рос через последовательные стадии, каждая опиралась на
понимание, доступное на тот момент.

Исходная идея: можно ли повысить достоверность ответов нейросетей —
прикладной поиск способа отличать сигнал от шума в потоке информации.

Первый рабочий прототип — отдельный агент DeepSeek.

Следующая стадия — попытка заточить систему под фриланс-направление
(остатки: таблицы chat_history, context_memory, orders,
suggest_feedback — удалены при чистке 2026-08, дамп сохранён).
Направление оставлено осознанно, когда стало ясно, что это угасающий
вектор.

Поворот к текущему фокусу — AI-агенты и токеномика как формирующийся
мир, где "квалификация сигнала" находит более естественное
применение. Отсюда STACK v10.5 — паук и паутина, Adaptive Signal Web.

Попытка подключения агента на Gemini — короткий эпизод, прекращённый
из-за проблем с регистрацией. Остатки (незакрытый краш-путь в коде)
найдены и исправлены аудитом 2026-07.

Текущая стадия: полный аудит системы (AUDIT_2026-07.md) и наведение
порядка в документации — часть этой эволюции, не разрыв с ней.

Практический вывод: артефакты прошлых стадий (мёртвые классы,
неиспользуемые таблицы, отсылки к утраченным версиям вроде
"Стек v9.6") — не аномалии, а естественные следы пройденного пути.

## ФИЛОСОФИЯ

выживание:    система работает непрерывно — основа всего
полезность:   сигнал должен быть ценен — сначала для Архитектора
масштаб:      нить за нитью, этап за этапом, без спешки
память:       накопленные данные — ров который нельзя купить
адаптивность: метрики и горизонты уточняются по ходу
интеграция:   не строить то что уже работает —
              подключать, квалифицировать, запоминать

Первый клиент — Архитектор. Что ценно для него → то и продаём
внешним. Не ищем бизнес-модель заранее — наблюдаем что работает.

Точка автономии: система покрывает расходы на себя.

Уникальная ценность MAIA — не сбор данных, а резонанс, квалификация
и память. Всё остальное — интеграция готового.

## DDA — DOCUMENTATION-DRIVEN ARCHITECTURE

Сейчас: документация описывает систему.
Цель: документация определяет систему.

Три слоя контракта:
  INVARIANTS.md = правила которые нельзя нарушить (ядро)
  DECISIONS.md  = политики — почему система устроена так
  RUNTIME.md    = желаемое состояние — что должно работать

Архитектура цели:
  Архитектор → LibreChat (единый интерфейс) →
  Claude Code (читает /docs/, три режима: Страж/Инспектор/
  Архитектор, git commit) → MAIA Core (nc_core.py, PostgreSQL, n8n)
  → React Topology (живая карта состояния)

Главный сдвиг: сейчас Архитектор управляет системой через агентов.
Цель: документация управляет системой, Архитектор управляет
документацией.

## РОЙ АГЕНТОВ

Дальний горизонт: MAIA перестаёт быть центром.

Сейчас: один паук, паутина расширяется.
Потом: внешние агенты потребляют сигнал через контролируемый endpoint.
Звезда: эмерджентные связи между агентами, MAIA — источник истины,
не точка контроля.

Принцип роя: агенты не подключаются к ядру напрямую · каждый
специализирован · связь через сигнал, не через код · рой возникает
сам.

Триггер перехода: появился внешний потребитель сигнала. Не раньше.

## ЭКОНОМИКА

Ров = данные + память + время работы. Нельзя купить — только
накопить.

Ресурсы не заливаются заранее. Триггер: упёрся в потолок по качеству
сигнала ИЛИ появился внешний потребитель.

⚠️ Обновление 2026-08-02: триггер по потолку сработал раньше
ожидаемого — не по качеству сигнала, а по объёму дневной квоты
OpenRouter. Разовое пополнение $10 произведено. Принцип "не заливать
заранее" остаётся в силе — сработавший триггер подтвердил метод,
не отменил его.

Возможные каналы (не план — наблюдение): Telegram синдикат ·
SaaS через LibreChat · Proof of Work блог · Farcaster · SimpleSwap/
Base L2/fiat gateways.

Принцип: не выбираем канал заранее — наблюдаем что резонирует.
